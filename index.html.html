PART · 01

这篇帮你用透。

你已经能跑起 claude 了，但大概率还停在"能用"——账号一切换就乱、VS Code 扩展连不上、报错只会重装。这篇就是带你把这几件事一次性弄明白。

你可能正卡在这些地方：

  • 装过"一键 Claude Code 安装脚本"，从此账号状态混乱
  • 明明登录了 Pro，对话却显示 gpt-5.4 这种诡异模型名
  • 同时用官方账号和中转站 API，但搞不清当前在用哪个
  • 代理配了一堆，VS Code 扩展还是"看不见"
  • 把 Claude Code 装在公司电脑，被网络管理坑过

核心理念只有一句：

把账号、网络、工具三件事彻底分开看待。
每一层独立运作，每一层都可解释。

PART · 02

先理解三层模型。

Claude Code 启动时按严格的优先级顺序决定"用哪个账号、连哪个服务器"。理解这三层的覆盖关系，是后面一切操作的基础。

正文 STEP·02 讲过这个三层模型，这里一句话回扣——Claude Code 按优先级从高到低读三层：① 环境变量层（ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN / ANTHROPIC_API_KEY，最高优先级，所有"中转站污染"都出在这层）→ ② 配置文件层（~/.claude 下的 json，cc-switch 操作的就是这里）→ ③ OAuth 凭证层（官方 Pro/Team 浏览器登录后存的）。这三层后面切换全靠它，记住一条就够：

核心规则

上层有值，下层就被忽略。这条规则解释了 99% 的"切换不生效"问题。所有看似复杂的"账号混乱"，本质都是某一层被偷偷写过、挡住了下层。

PART · 03

把代理这层配干净。

前提：你已经照正文把 claude 装好了，本机也有一个能正常工作的代理软件。这一节只做正文没展开的一件事——让 Claude Code 正确、稳定地走你的代理，不污染、不串台。

测试代理可达性（关键：用 curl.exe）

PowerShell 里 curl 是 Invoke-WebRequest 的别名，不认识 -x 参数。必须用 curl.exe 调真正的 curl 程序。

PowerShellcurl.exe -x http://127.0.0.1:10808 -I https://api.anthropic.com
curl.exe -x http://127.0.0.1:10808 -I https://claude.ai

看到 HTTP/... 开头的响应（200/401/403 都算通）才能往下走。把 10808 换成你代理软件实际的 HTTP 端口。

小坑

Claude Code 完全不认 SOCKS 协议。必须用代理软件的"HTTP 端口"或"混合端口"，不能用纯 SOCKS5 端口。

永久配置代理环境变量

这一步配完，所有终端、所有 Claude Code 子进程都自动带代理，不用每次手动设置。

PowerShell# 用户级永久变量（把 10808 换成你的实际端口）
[System.Environment]::SetEnvironmentVariable('HTTPS_PROXY','http://127.0.0.1:10808','User')
[System.Environment]::SetEnvironmentVariable('HTTP_PROXY','http://127.0.0.1:10808','User')
[System.Environment]::SetEnvironmentVariable('NO_PROXY','localhost,127.0.0.1','User')

关掉所有终端窗口，重开后验证：

PowerShellecho $env:HTTPS_PROXY
# 应该输出 http://127.0.0.1:10808

创建 settings.json（Claude Code 本地配置）

路径 C:\Users\<你的用户名>\.claude\settings.json。只写代理，不写 base URL、不写 token，保持干净。

settings.json{
  "env": {
    "HTTPS_PROXY": "http://127.0.0.1:10808",
    "HTTP_PROXY": "http://127.0.0.1:10808",
    "NO_PROXY": "localhost,127.0.0.1"
  }
}

确认 claude 用哪个命令调

（claude 你已经照正文装好了。）Windows 上要留意：可能同时存在 claude.cmd 和 claude.ps1，统一用 claude.cmd 调用，避免和后面那套自定义 PowerShell 函数冲突。

装 VS Code 扩展

  1. VS Code 扩展市场搜 Claude Code（作者 Anthropic），装上
  2. 关掉整个 VS Code 进程（不是关窗口）
  3. 从终端启动：code .（让 VS Code 继承环境变量）
  4. 打开扩展面板，CLI 已登录的凭证会自动复用，不用再登一次
macOS 用户额外注意

从 Dock/Launchpad 启动的 VS Code 不会继承你 .zshrc 里 export 的任何变量。需要额外跑 launchctl setenv HTTPS_PROXY http://127.0.0.1:7890，或永远从终端 code . 启动。

PART · 04

账号切换：willton 体系。

官方 Pro 是主力，中转站 API 是限额时的备胎。这一节给你一套可记忆的命令，把两者无缝串起来。

命令一览

willton

启动 Claude Code，使用官方 Pro/Team 账号（OAuth）。

用于：日常使用、配额未用完时
willtonos

启动 Claude Code，使用 cc-switch 当前选中的中转站。

用于：官方限额耗尽、临时救急
willtonos <name>

指定切到 cc-switch 里某个 Provider，例如 willtonos closeai。

用于：在多家中转站间切换
lscc

列出 cc-switch 里所有可用的 Provider（名字 + URL）。

用于：忘了配过哪些中转站时

设计思路

这套命令的精妙之处在于把三个机制整合到了一起：

机制在这套方案里的角色
willton 的重置机制启动前清空环境变量层，防止上层覆盖
cc-switch 的 JSON 管理当配置数据库，所有 token 集中存储，GUI 可视化
willtonos 的遥控逻辑命令行调用 cc-switch 的切换功能，GUI 视觉同步

完整工作流

日常使用# 1. 列出有哪些可用账号
> lscc
Available Providers in cc-switch:
  - Claude Official (https://api.anthropic.com)
  - api.iamhc (https://api.iamhc.cn/)
  - closeai (https://api.closeai-proxy.xyz/anthropic)

# 2. 平时用官方
> willton
[willton] Official Pro/Team (OAuth)

# 3. 限额快用完，切到中转站
> willtonos iamhc
[CCSwitch] -> api.iamhc (https://api.iamhc.cn/)

# 4. 第二天重置，切回官方
> willton

每次切换都验证一次

终端打印的内容只是函数自报，真正的事实在 /status 里。养成进入 Claude 界面立刻跑 /status 的习惯，看 Anthropic base URL 这一行是不是你期望的。

PART · 05

VS Code 使用要点。

VS Code 扩展和 CLI 共享凭证，但是是两个独立的进程。理解它们的边界，能避开 90% 的"扩展看不见登录"问题。

VS Code 的网络模型

VS Code 是 Electron 应用，网络请求分两部分：

  • 主进程（UI、扩展市场、插件更新）：默认尝试读取系统代理，但在 macOS / Linux 上经常失效
  • 扩展子进程（比如 Claude Code 扩展）：底层是独立 Node.js 进程，完全不会自动读取系统代理，只读取 VS Code 显式配置的代理或环境变量
VS Code 启动陷阱

从 Dock / 任务栏 / 桌面图标启动的 VS Code，拿不到任何 shell 环境变量。这是 macOS 用户最常踩的坑——明明在终端 export 了代理，扩展依然报网络错误。

正确启动方式

永远从终端启动 VS Code，让它继承当前 shell 的所有环境变量：

PowerShell / Terminal# Windows / macOS / Linux 都一样
code .

扩展专属代理配置（双保险）

在 VS Code 的 settings.json 里（按 Ctrl+Shift+P → "Open User Settings (JSON)"），加上：

VS Code settings.json{
  "claudeCode.environmentVariables": {
    "HTTPS_PROXY": "http://127.0.0.1:10808",
    "HTTP_PROXY": "http://127.0.0.1:10808",
    "NO_PROXY": "localhost,127.0.0.1"
  },
  "http.proxySupport": "on",
  "http.proxy": "http://127.0.0.1:10808"
}

让 VS Code 永远走官方账号

推荐工作流：VS Code 扩展永远用官方 Pro，命令行才切中转站。原因是 VS Code 一旦切到中转站，所有"代码补全、长上下文、artifacts"等高级特性可能会受中转站接口兼容性影响。

实现方式很简单：

  • 启动 VS Code 时不要从跑过 willtonos 的终端启动（避免污染环境变量）
  • 新开一个干净的 PowerShell，跑 code .
  • 或者把 willton-code 函数加到 Profile（见附录）

扩展行为对照表

启动方式是否继承终端代理读哪份凭证
桌面图标 / 任务栏❌ 不继承~/.claude/.credentials.json
已经在运行（之前打开的）❌ 不会更新启动时读的那份
从干净的终端 code .✅ 继承~/.claude/.credentials.json
从跑过 willtonos 的终端 code .⚠️ 继承中转站变量被环境变量覆盖

PART · 06

排错速查：30 秒定位。

任何 Claude Code 问题，按这个顺序自检，几乎都能在 30 秒内定位到根本原因。

第一动作：跑 /status

这是排查任何问题的第一步。比所有 debug 日志都管用。重点看四个字段：

字段正常状态（官方 Pro）异常征兆
Email你的真实邮箱不认识的 hotmail / outlook 地址 → 登错账号
Login methodClaude Pro / Team accountAPI key → 走的是中转站
Anthropic base URL空 或 api.anthropic.com任何第三方域名 → 环境变量被污染
ModelSonnet / Opus / Haikugpt-* / 其他名字 → 中转站包装的非 Claude 模型

完整自检命令

PowerShell# 1. 代理通不通
curl.exe -x http://127.0.0.1:10808 -I https://api.anthropic.com

# 2. 环境变量是否干净
echo "BASE_URL = $env:ANTHROPIC_BASE_URL"
[System.Environment]::GetEnvironmentVariable('ANTHROPIC_BASE_URL','User')
[System.Environment]::GetEnvironmentVariable('ANTHROPIC_BASE_URL','Machine')

# 3. 代理变量在不在
echo "HTTPS_PROXY = $env:HTTPS_PROXY"

# 4. settings.json 干净不干净
type $env:USERPROFILE\.claude\settings.json

常见症状对照表

症状根因解法
Retrying in Xs · attempt N/10API 请求被中转站拖住 或 当前进程没代理跑 /status，看 base URL 是否被污染
显示 gpt-5.4 等非 Claude 模型连了第三方中转站，不是官方清环境变量层，跑 willton
VS Code 扩展要求重新登录从图标启动，没继承环境关掉 VS Code，从终端 code . 启动
浏览器登录回调卡死NO_PROXY 没设，localhost 被代理拦了加 NO_PROXY=localhost,127.0.0.1
PowerShell 报 "curl 找不到参数 x"用了 PS 别名而非真 curl用 curl.exe
PowerShell Profile 报"数组索引表达式"含中文 Profile 被存成 GBK 编码用 VS Code 重存为 UTF-8 with BOM
cc-switch 切换没生效环境变量层有值在挡住清环境变量，再切

遇到不确定的问题怎么求救

  1. 跑 /status，截图
  2. 跑 claude.cmd --debug，进 Claude 界面发一句"你好"，等出错
  3. 找 debug 日志：路径在 ~/.claude/debug/<session-id>.txt
  4. 用 findstr 过滤关键词：
PowerShellfindstr /i "error fail ECONN abort timeout 429 503" $env:USERPROFILE\.claude\debug\<session>.txt

PART · 07

红线规则。

教学时一定要强调的几条铁律，违反任何一条都会导致前面的努力归零。

红线 01

不要装"一键中转"脚本。它们会在你不知情时设置 ANTHROPIC_BASE_URL 永久环境变量，把请求和对话内容导向第三方。我们这次排查到底，根源就是这个。

红线 02

不要在 settings.json 里写 base URL 或 token。这个文件应该只放代理配置。账号信息走 cc-switch 或环境变量，分层管理。

红线 03

任何"免费 / 低价 Claude API"网站要警惕。99% 是中转站，对话内容会被第三方记录。敏感代码、业务逻辑、客户数据，永远不要在中转站上跑。

红线 04

切换账号后必须看 /status。函数打印的提示行可能撒谎（硬编码字符串），但 /status 反映的是 Claude Code 启动时真正读到的配置。这是唯一可靠的事实来源。

红线 05

不要混用账号管理工具。选定一套工作流（cc-switch 或纯命令行）就别再装别的。多套工具同时管同一个 JSON 文件，必出意外覆盖。

APPENDIX

附录：完整 Profile。

直接复制下面这段到 $PROFILE 即可使用。打开方式：notepad $PROFILE。

Microsoft.PowerShell_profile.ps1# =====================================================
# Claude Code Account Switcher · willton edition
# =====================================================

# --- 配置 cc-switch 配置文件路径（按你系统实际位置调整）---
$global:ccSwitchConfig = "$env:APPDATA\cc-switch\config.json"
$global:claudeConfig   = "$env:USERPROFILE\.claude\.claude.json"

# --- 核心函数：调用 cc-switch 切换到指定 Provider ---
function Switch-CCProvider {
    param([string]$ProviderName)

    if (-not (Test-Path $ccSwitchConfig)) {
        Write-Host "cc-switch config not found: $ccSwitchConfig" -ForegroundColor Red
        return $false
    }

    $ccConfig = Get-Content $ccSwitchConfig -Raw | ConvertFrom-Json
    $provider = $ccConfig.providers | Where-Object { $_.name -eq $ProviderName }

    if (-not $provider) {
        Write-Host "Provider '$ProviderName' not found" -ForegroundColor Red
        return $false
    }

    $claudeJson = Get-Content $claudeConfig -Raw | ConvertFrom-Json
    $claudeJson.primaryApiKey    = $provider.apiKey
    $claudeJson.anthropicBaseUrl = $provider.baseUrl
    $claudeJson | ConvertTo-Json -Depth 100 | Set-Content $claudeConfig -Encoding UTF8

    Write-Host "[CCSwitch] -> $ProviderName ($($provider.baseUrl))" -ForegroundColor Green
    return $true
}

# --- willton: 切到官方 Pro/Team 账号 ---
function willton {
    Remove-Item Env:ANTHROPIC_BASE_URL   -ErrorAction SilentlyContinue
    Remove-Item Env:ANTHROPIC_AUTH_TOKEN -ErrorAction SilentlyContinue
    Remove-Item Env:ANTHROPIC_API_KEY    -ErrorAction SilentlyContinue
    Switch-CCProvider "Claude Official" | Out-Null
    Write-Host "[willton] Official Pro/Team" -ForegroundColor Green
    claude.cmd @args
}

# --- willtonos: 切到指定中转站 ---
function willtonos {
    param([string]$Provider = "api.iamhc")

    # 别名映射（按需扩展）
    $aliasMap = @{
        'iamhc'   = 'api.iamhc'
        'closeai' = 'closeai'
    }
    if ($aliasMap.ContainsKey($Provider)) {
        $Provider = $aliasMap[$Provider]
    }

    Remove-Item Env:ANTHROPIC_BASE_URL   -ErrorAction SilentlyContinue
    Remove-Item Env:ANTHROPIC_AUTH_TOKEN -ErrorAction SilentlyContinue
    Switch-CCProvider $Provider | Out-Null
    Write-Host "[willtonos] -> $Provider" -ForegroundColor Yellow
    claude.cmd @args
}

# --- lscc: 列出所有可用的 Provider ---
function List-CCProviders {
    if (-not (Test-Path $ccSwitchConfig)) {
        Write-Host "cc-switch config not found" -ForegroundColor Red
        return
    }
    $config = Get-Content $ccSwitchConfig -Raw | ConvertFrom-Json
    Write-Host "Available Providers in cc-switch:" -ForegroundColor Cyan
    $config.providers | ForEach-Object {
        Write-Host "  - $($_.name) ($($_.baseUrl))" -ForegroundColor Gray
    }
}
Set-Alias -Name lscc -Value List-CCProviders

# --- willton-code: 用官方账号启动 VS Code ---
function willton-code {
    Remove-Item Env:ANTHROPIC_BASE_URL   -ErrorAction SilentlyContinue
    Remove-Item Env:ANTHROPIC_AUTH_TOKEN -ErrorAction SilentlyContinue
    Remove-Item Env:ANTHROPIC_API_KEY    -ErrorAction SilentlyContinue
    Write-Host "[willton-code] VS Code (Official)" -ForegroundColor Cyan
    code @args
}
使用提示

编辑 Profile 后，重开 PowerShell 才会生效。或者在当前会话里跑 . $PROFILE 手动重载。
如果你的 Profile 包含中文注释，用 VS Code 打开它（code $PROFILE），右下角确认编码是 UTF-8 with BOM 再保存——否则 PowerShell 5 会乱码报错。
