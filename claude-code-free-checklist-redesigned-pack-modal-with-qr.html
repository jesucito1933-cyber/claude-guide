PART · 02

新手最容易踩的10 个坑。

这些坑不是“技术难”，而是很多人没分清层级：到底是账号问题、网络问题、终端问题，还是 VS Code 扩展问题。

把“一键安装”当成万能解法

很多脚本会悄悄写入环境变量或第三方地址。短期看似方便，后面排查会非常痛苦。

不知道自己当前连的是官方还是第三方

看到模型名、Base URL、登录方式异常时，先别继续用，先确认当前请求到底发到哪里。

把账号、网络、工具混成一个问题

登录失败不一定是账号错，扩展打不开不一定是 Claude Code 坏了，终端能通也不代表 VS Code 能通。

代理端口选错

很多代理软件同时有 HTTP、SOCKS、混合端口。Claude Code 对网络环境比较挑，端口错了就会一直重试。

PowerShell 里把 curl 用错

Windows 里有时 curl 不是你以为的那个 curl，新手常因此误判网络不通。

VS Code 从桌面图标启动

从图标启动的 VS Code 不一定继承终端环境，导致 CLI 正常、扩展异常。

把敏感代码丢给不明中转站

低价或免费接口不等于安全。项目代码、业务逻辑、客户资料不要随便交给不明第三方。

多个账号管理工具混着用

多个工具同时改同一份配置文件，很容易互相覆盖，最后你也不知道是谁改坏的。

装好就以为会用了

Claude Code 的价值不在“安装成功”，而在会拆任务、会给上下文、会让它参与真实项目。

没写售后边界

如果你是帮别人配置，一定要提前说明：只解决当次问题，不承诺第三方环境长期稳定。

PART · 03

必须理解的三层模型。

大多数“怎么切都不生效”的问题，都来自同一个原因：上层配置挡住了下层配置。

01
环境变量层

优先级最高。只要这里有值，下面的配置很可能全部被覆盖。

BASE URL / TOKEN / API KEY
02
配置文件层

很多图形化工具或账号切换工具会改这一层。适合管理，但怕多工具混用。

.claude 配置文件
03
OAuth 凭证层

官方账号登录后的凭证。当前两层没有覆盖时，才会真正读到这里。

官方账号登录凭证
一句话记住

上层有值，下层就容易被挡住。所以遇到异常，不要第一时间重装，而是先确认是哪一层在生效。

PART · 06

5 条红线，别乱碰。

这些内容保留在免费版里，因为它们比“具体命令”更重要。先不踩雷，再谈上手。

红线 01

不要乱装来源不明的一键脚本。尤其是会替你写入 Base URL、Token、API Key 的脚本。

红线 02

不要把敏感代码和业务数据交给不明第三方。低价接口的风险，往往不在价格，而在数据流向。

红线 03

不要混用多个账号切换工具。选定一套工作流就坚持用，否则配置文件会被反复覆盖。

红线 04

不要把“安装成功”等同于“真正会用”。真正的价值在任务拆解、上下文组织和项目落地。

红线 05

如果你帮别人配置，必须提前写清服务边界。一次性协助不是长期免费售后。
