BONUS · 02

排错前，先理解三层模型。

Claude Code 出问题时，不要凭感觉重装。先判断它当前到底读到了哪一层配置。绝大多数“切换不生效”，本质都是上层配置挡住了下层。

01
环境变量层

最高优先级。一旦设置，配置文件和官方登录凭证都会被忽略。很多“一键脚本污染”都发生在这里。

ANTHROPIC_BASE_URL
ANTHROPIC_AUTH_TOKEN
ANTHROPIC_API_KEY
02
配置文件层

cc-switch 等工具通常改的是这一层。环境变量为空时，这一层才会生效。

~/.claude/.claude.json
~/.claude/settings.json
03
OAuth 凭证层

官方 Pro / Team 账号通过浏览器登录后留下的凭证。前两层都没值时才会读到。

~/.claude/.credentials.json
核心规则

上层有值，下层就被忽略。所以不要一出问题就重装，先看环境变量有没有异常，再看配置文件，最后看官方账号登录状态。

典型污染状态

conceptual# 你以为自己切回了官方，实际状态可能是：
环境变量层:    ANTHROPIC_BASE_URL = "某个第三方服务地址"  🔴 仍然存在
配置文件层:    cc-switch = Claude Official                 ✅ 但被盖住
OAuth 层:       你的 Pro 账号凭证                         ✅ 但被盖住

# 结论：不是账号丢了，是上层挡住了下层。

BONUS · 03

已购用户复查清单：别急着重装。

正文已经讲过安装流程。这里不再重复从零部署，只给你一张“出问题时按顺序查”的清单。每次卡住，都先从这里开始。

最稳顺序

先确认主链路，再处理进阶配置

CLI 能启动 /status 干净 官方账号能用 VS Code 继承环境 最后再切第三方

新手最容易犯的错，是还没确认官方链路干净，就同时改环境变量、cc-switch 和 VS Code。这样一旦出错，你根本不知道是哪一层导致的。

确认 CLI 能启动

Terminalclaude --version
claude doctor

如果这一步不通，先回正文安装部分，不要急着配置模型或 VS Code。

确认 /status 是否干净

Claude Code/status

重点看 Email、Login method、Anthropic base URL、Model。只要 base URL 出现陌生域名，优先排查环境变量层。

检查环境变量有没有污染

PowerShellecho "BASE_URL = $env:ANTHROPIC_BASE_URL"
[System.Environment]::GetEnvironmentVariable('ANTHROPIC_BASE_URL','User')
[System.Environment]::GetEnvironmentVariable('ANTHROPIC_BASE_URL','Machine')

这里如果有第三方地址，官方登录很可能被挡住。先清理，再重开终端验证。

确认 VS Code 是从项目目录启动

Terminalcd your-project
code .

不要从桌面图标随便打开。终端能跑，VS Code 不认，大概率是环境没有继承。

BONUS · 05

VS Code 使用要点。

终端版跑通之后，再碰 VS Code。VS Code 扩展和 CLI 共享凭证，但它们是两个独立进程，最常见的问题是“终端能用，扩展不认”。

正确启动方式

永远从项目目录启动 VS Code，让它继承当前 shell 的环境变量：

Terminalcd your-project
code .

扩展专属代理配置（双保险）

如果终端能用、VS Code 仍然不通，可以在 VS Code 的 settings.json 里显式写入代理：

VS Code settings.json{
  "claudeCode.environmentVariables": {
    "HTTPS_PROXY": "http://127.0.0.1:10808",
    "HTTP_PROXY": "http://127.0.0.1:10808",
    "NO_PROXY": "localhost,127.0.0.1"
  },
  "http.proxySupport": "on",
  "http.proxy": "http://127.0.0.1:10808"
}

建议：VS Code 先保持官方账号

新手阶段，不建议在 VS Code 里来回切第三方服务。扩展环境一旦乱，排错成本很高。推荐：VS Code 保持官方，命令行再做切换实验。

现象优先检查处理方向
终端能用，VS Code 不认是否从 code . 启动关掉 VS Code，从项目目录重开
扩展一直要求重新登录凭证 / 环境是否继承先终端 /status，再修扩展
VS Code 走了奇怪模型环境变量是否污染清理后重启整个 VS Code 进程

排错速查：30 秒定位。

任何 Claude Code 问题，先不要重装。按下面顺序查，通常能很快判断是账号、网络、配置文件还是环境变量的问题。

第一动作：跑 /status

字段正常状态异常征兆
Email你的真实邮箱不认识的邮箱 → 登错账号
Login methodClaude Pro / Team accountAPI key → 当前可能走第三方服务
Anthropic base URL空或 api.anthropic.com第三方域名 → 上层配置覆盖
ModelSonnet / Opus / Haikugpt-* 或陌生名 → 当前不是官方模型链路

完整自检命令

PowerShell# 1. 代理是否可达
curl.exe -x http://127.0.0.1:10808 -I https://api.anthropic.com

# 2. 环境变量是否污染
echo "BASE_URL = $env:ANTHROPIC_BASE_URL"
[System.Environment]::GetEnvironmentVariable('ANTHROPIC_BASE_URL','User')
[System.Environment]::GetEnvironmentVariable('ANTHROPIC_BASE_URL','Machine')

# 3. 代理变量是否存在
echo "HTTPS_PROXY = $env:HTTPS_PROXY"

# 4. settings.json 是否写了不该写的东西
type $env:USERPROFILE\.claude\settings.json

BONUS · 07

红线规则。

这些不是“建议”，而是为了防止你把环境越改越乱。违反任何一条，都可能让前面的努力归零。

不要装来路不明的“一键中转”脚本

它们可能在你不知情时写入 ANTHROPIC_BASE_URL，后续怎么切都不生效。

不要在 settings.json 里写 base URL 或 token

这个文件尽量只放代理配置。账号信息和第三方服务配置要分层管理。

敏感项目不要跑第三方服务

代码、业务逻辑、客户数据，都不要放到不可信的第三方服务上处理。

切换账号后必须看 /status

提示文案可能会误导你，/status 才是当前真实状态。

不要混用多套账号管理工具

选定一套工作流就先用到底。多套工具同时改同一个配置文件，最容易互相覆盖。

APPENDIX

附录：最小 Profile 模板。

完整工作流适合已经跑通官方账号、并且想长期切换环境的人。第一次安装不要急着复制这里；先把正文跑通，再回来改。

复制前先改

下面是最小模板，不是万能脚本。你至少要确认：cc-switch 路径、Provider 名称、代理端口、PowerShell 编码。复制后先跑 lscc，再跑 willton。

Microsoft.PowerShell_profile.ps1# Claude Code mini workflow · edit before use
$global:ccSwitchConfig = "$env:APPDATA\cc-switch\config.json"

# 列出 cc-switch Provider
function lscc {
  if (-not (Test-Path $ccSwitchConfig)) {
    Write-Host "cc-switch config not found" -ForegroundColor Red
    return
  }
  $cc = Get-Content $ccSwitchConfig -Raw | ConvertFrom-Json
  $cc.providers | ForEach-Object { Write-Host "- $($_.name)  $($_.baseUrl)" }
}

# 回到官方：清掉可能覆盖官方登录的变量，再启动
function willton {
  Remove-Item Env:ANTHROPIC_BASE_URL -ErrorAction SilentlyContinue
  Remove-Item Env:ANTHROPIC_AUTH_TOKEN -ErrorAction SilentlyContinue
  Remove-Item Env:ANTHROPIC_API_KEY -ErrorAction SilentlyContinue
  claude
}

# 备用模式：这里不写死 provider，建议先用 cc-switch GUI 切换
function willtonos {
  claude
}
为什么精简

完整版 Profile 会涉及 Provider 写入、JSON 修改、环境变量重置和 GUI 同步。它适合进阶用户，不适合第一次安装。作为赠品，这里保留最小可读版本，避免新手复制后把环境改乱。
